# Marks501 — спецификация

## v0.1 — сохраняемая функциональность

| Требование | Критерий готовности |
| --- | --- |
| Аддон загружается | Появляется в списке модификаций WoW. |
| Открытие торговца | Автоматически выводит сводку. |
| Безопасность | Сканирование и открытие торговца не продают и не перемещают предметы. |
| Пустые сумки | Не вызывают ошибок. |
| Отсутствие данных о цене | Обрабатывается без падения. |

## v0.2 — метки «на продажу»

Цель: WoW Forever 1.60.1, Interface 16001, Lua 5.1. Метка обозначает намерение продать предмет. Поставить её можно и на предмет, который торговец не купит.

### Требования и критерии приёмки

| Требование | Критерий |
| --- | --- |
| Настраиваемый хоткей на macOS | В штатных настройках клавиш WoW в разделе `Marks501` есть действие «Пометить / снять метку „на продажу“». Изначально клавиша не назначена. Можно назначить, изменить и снять сочетание без автоматической перезаписи других биндов. Назначенное сочетание работает после перезахода. |
| Ручная метка в сумках | При наведении на занятый слот хоткей сразу показывает или скрывает значок мешочка без эмблемы. Тень начинается в нижнем левом углу иконки предмета и плавно рассеивается к центру. Значок не перекрывает счётчик стопки и не перехватывает мышь. |
| Область действия | Штатные рюкзак и четыре сумки в раздельном и объединённом режимах. Нажатие над пустым слотом, вне этих сумок, при вводе текста или перетаскивании предмета не меняет меток. Банк, экипировка и сторонние интерфейсы сумок не поддерживаются. |
| Идентичность экземпляра | Если две стопки имеют один `itemID`, метка появляется только на выбранной. При переносе и сортировке она следует за GUID, а новый предмет в прежнем слоте её не получает. Без доступного GUID метка не ставится. |
| Разделение и объединение | Метка остаётся только у стопки, унаследовавшей отмеченный GUID, независимо от размера. Новый GUID метку не наследует; если отмеченный GUID исчез, у результата метки нет. |
| Хранение | Метки отдельны для каждого персонажа. После `/reload` и обычного перезахода они отображаются на предметах, сохранивших тот же GUID. Снятая метка не восстанавливается. |
| Совместимость и безопасность | Автоматическая сводка при открытии торговца по-прежнему учитывает все серые предметы независимо от меток. Сам хоткей не продаёт, не использует и не перемещает предметы. |
| Снять все метки | `/bm clear` заменяет `/bm scan`. Команда удаляет все сохранённые метки текущего персонажа, сразу обновляет значки и кнопку торговца и не трогает сами предметы. |
| Штатная продажа хлама | Та же кнопка активна, если есть обычный хлам или подходящие помеченные стопки. Штатное окно подтверждения сообщает число дополнительных стопок. Отмена ничего не продаёт; подтверждение запускает штатную продажу хлама и добавляет подходящие помеченные стопки. |
| Ограничения продажи | Серые предметы продаёт только штатный обработчик. Дополнительная продажа пропускает сумки, исключённые пользователем, а также непродаваемые, заблокированные и возвратные предметы. Стопка, у которой после открытия диалога сменились слот, GUID, размер или метка, не продаётся этим подтверждением. |
| Локализация | Название хоткея, сводка, ответ на `/bm clear` и дополнение к подтверждению выбираются по языку клиента. Для неизвестной локали используется английский. |

### Технические решения и риски

- `SaleMarks.lua` хранит `GUID → true` в `SavedVariablesPerCharacter` и читает точный GUID по координатам слота. Отсутствие GUID в открытых сумках не повод удалять его из сохранения: предмет мог быть временно перемещён. Поэтому записи об исчезнувших предметах могут остаться в базе.
- `BagMarks.lua` обновляет пассивный значок при открытии сумок, переназначении кнопок и обновлении предметов Blizzard. Штатные обработчики не заменяются. Имена методов UI подтверждены в исходниках Forever 1.60.1, но это внутренний интерфейс Blizzard: при смене клиента необходима повторная проверка.
- Стабильность GUID на сервере и поведение при операциях со стопками нельзя подтвердить только по сигнатурам API. Если клиент меняет GUID, сопоставления по типу или позиции не будет.
- Для macOS используются штатные бинды: доступность конкретных сочетаний зависит от WoW, раскладки и системных назначений. `⌘` не требуется.
- `MerchantSales.lua` расширяет существующее окно подтверждения и ждёт события Blizzard о принятии. Дополнительная продажа использует тот же API, что и штатный правый клик по слоту, только при активном взаимодействии с торговцем и после повторной проверки стопки. Если окно подтверждения не найдено, аддон не продаёт помеченные вещи. Ограничения выкупа остаются штатными.
- `C_Container.UseContainerItem` ограничен вне допустимого контекста. Если клиент блокирует вызов у торговца, аддон прерывает дополнительную продажу без повторных попыток и не снимает метки с оставшихся предметов.

### План реализации и проверки

1. Добавить хранение по GUID на персонажа, без изменений в сканере и сводке v0.1.
2. Добавить нативный бинд без клавиши по умолчанию, поиск штатной кнопки под курсором и пассивный значок.
3. Проверить в Lua 5.1 переключение метки, одинаковые предметы, перенос, переиспользование кнопок, отрицательные сценарии и повторную загрузку сохранения. Повторить тесты v0.1.
4. В WoW Forever на macOS назначить свободное сочетание. Проверить оба режима сумок, сортировку, разделение и объединение стопок, `/reload`, выход и повторный вход.
5. Проверить у торговца на недорогих предметах: только хлам, только помеченное, обе категории, отмена, исключённая сумка и закрытие торговца перед подтверждением. Проверить, что добавленный текст помещается в диалог и соответствует языку клиента.
